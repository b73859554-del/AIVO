# AIVO Phase 3 backend contract

This document defines the client/server contract used by the Phase 3 Android client. It is not a backend implementation or a claim that any endpoint is deployed. Only an AIVO-owned HTTPS service may implement these routes. The client never falls back to another product, service, or legacy URL.

## Configuration and environments

The Android runtime reads one canonical endpoint, `BuildConfig.AIVO_PROXY_URL`.

| Selected environment | Gradle selector | Build-time endpoint input | Application ID |
|---|---|---|---|
| Development (default) | `AIVO_ENVIRONMENT=development` | `AIVO_PROXY_URL` | `io.aivo.app.dev` |
| Staging | `AIVO_ENVIRONMENT=staging` | `AIVO_STAGING_PROXY_URL` | `io.aivo.app.staging` |
| Production | `AIVO_ENVIRONMENT=production` | `AIVO_PRODUCTION_PROXY_URL` | `io.aivo.app` |

Use the corresponding Gradle property (`-PAIVO_ENVIRONMENT=...`, `-PAIVO_PROXY_URL=...`, etc.) or environment variable. A staging/production build with its own endpoint unset remains offline; it does not inherit the development endpoint. The app accepts only HTTPS URLs with a hostname and without user info, query, fragment, or dot-segment paths. Cleartext traffic is disabled.

Google Web OAuth client identifiers are public identifiers passed to Credential Manager:
`AIVO_GOOGLE_WEB_CLIENT_ID`, `AIVO_GOOGLE_WEB_CLIENT_ID_STAGING`, and
`AIVO_GOOGLE_WEB_CLIENT_ID_PRODUCTION`. They are not client secrets. The Android package and signing certificate used in Google OAuth registration must match the selected build's application ID and signing identity.

## Common transport rules

- The Android client constructs only the fixed `/v1/...` paths below under the configured AIVO base path.
- Requests use HTTPS, `Accept: application/json`, JSON request bodies where applicable, finite timeouts, and redirects disabled.
- `X-AIVO-Environment` contains `development`, `staging`, or `production`.
- Session-protected routes use `Authorization: Bearer <access_token>`.
- Success responses use JSON except an explicitly empty successful response. Errors may return `{"message":"safe user-facing error"}`; clients bound and sanitize that message. Do not return secrets, stack traces, internal provider details, or account-existence information.
- The server validates every request, authorizes user/resource relationships, rate-limits auth/recovery/chat endpoints, and never trusts client-provided roles or account identifiers.
- AI-provider keys, OAuth client secrets, signing secrets, and service credentials remain server-side.

## Authentication routes

| Method and path | Auth | Request | Success |
|---|---|---|---|
| `POST /v1/auth/email/sign-up` | None | `{"email":"...","password":"..."}` | Session JSON, only when server policy permits sign-in |
| `POST /v1/auth/email/sign-in` | None | `{"email":"...","password":"..."}` | Session JSON |
| `POST /v1/auth/email/password-reset` | None | `{"email":"..."}` | Generic success whether or not the address is registered |
| `POST /v1/auth/google` | None | `{"id_token":"...","nonce":"..."}` | Session JSON after server-side token and nonce validation |
| `POST /v1/auth/refresh` | None | `{"refresh_token":"..."}` | Rotated session JSON |
| `POST /v1/auth/logout` | Bearer | `{"refresh_token":"..."}` | Empty or JSON success after revocation |
| `DELETE /v1/account` | Bearer | No body | Success only after server-side account/data deletion |

Session JSON:

```json
{
  "access_token": "opaque-or-signed-short-lived-token",
  "refresh_token": "rotating-refresh-token",
  "expires_in": 3600,
  "email": "account@example.test"
}
```

The app stores this session only as AES-GCM encrypted data using an Android Keystore key. It never persists passwords or Google ID tokens. The server must validate Google ID tokens (signature, issuer, audience, expiry, and nonce) rather than trusting client-supplied profile fields. Refresh responses rotate both tokens. A `401`/`403` during refresh invalidates the local session.

## Chat route

`POST /v1/chat/completions` requires a bearer token. Example request:

```json
{
  "conversation_id": "client-generated-uuid",
  "preferred_language": "en",
  "messages": [
    {"role": "user", "content": "Please explain this image."}
  ],
  "attachments": [
    {"name": "photo.png", "mime_type": "image/png", "data": "base64-encoded-bytes"}
  ]
}
```

`preferred_language` is `en`, `hi`, or `ur`; the backend should answer in that language. Supported attachments are images, PDF, and plain text, with each selected file limited to 4 MiB by the client and the serialized request bounded at 8 MiB. The server must independently enforce limits and inspect file content rather than trusting names/MIME supplied by the device.

Success response:

```json
{
  "message": {"role": "assistant", "content": "A real response generated by the configured AIVO service."},
  "request_id": "server-generated-request-id"
}
```

The client stores user/assistant conversation history in an encrypted app-private file, excluded from backup/transfer. It accepts only a non-empty `assistant` message from the real AIVO response; it does not synthesize a success or fallback answer. Stop disconnects/cancels the client request but cannot promise that server-side inference stopped after receipt.

Voice input does not add a backend route or upload raw audio. The Android recognition service returns a transcript to the composer; AIVO sends only the transcript as ordinary user message text after the user reviews and taps Send.

## External setup and unverified behavior

No AIVO backend is implemented or deployed by this repository. No endpoint, Google OAuth registration, signing fingerprint, recovery-mail provider, or AI-provider credential is configured. Therefore the real email/Google session flow, backend ID-token validation, AI generation, server-side deletion, and fresh-install-to-real-response journey remain unverified and require those external AIVO services. Do not substitute a mock service or legacy backend.
